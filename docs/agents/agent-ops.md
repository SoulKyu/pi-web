# Agent Ops: agent cards and tasks

## Agent Ops (`lib/agent-ops/`, `app/api/agent-ops/**`, `components/agents/*`)
- **Files:** `overview.ts` (cards from profiles + sessions, `readAgentProfileRef` with a fingerprint cache), `task-store.ts` (JSON task files), `runner.ts` (claims, slots, deadline), `prompt-run.ts` (prompt send, `done`, trigger tool check), `spawn.ts` (`startAgentProfileRun`), `kick.ts` (`kickRunner`, `recoverOnce`), `trigger-store.ts`. Routes: `overview`, `tasks` (GET/POST), `tasks/[id]` (POST steer, DELETE cancel). UI: `AgentsPanel`, `AgentTasks`, `AssignTaskDialog`, `task-view`.
- **Cards are an allowlist.** `AgentCard` never carries `systemPrompt`, `tools` or `filePath`. An orphan card (sessions of a profile no longer defined) sets `orphan: true` and an empty description; the panel renders the translated `agentOps.orphan`, never an English string from the server. The profile-ref cache is cleared at 20000 entries; above that every poll re-reads every file.
- **Terminal states are immutable.** `updateTask` throws on a task already `completed` / `failed` / `cancelled`; the runner's `finish()` re-reads and skips instead. `attachSession` never throws, even on a terminal task.
- **Claims use a `wx` lock** (`claimTask`), re-read after the claim so a task finished in between is not run. Task ids are UUID-guarded in the store (`isValidId`), so a route param can never build a path outside the store.
- **Cancel writes `cancelled` before sending abort.** A cancel during start finds no session to abort, so the runner re-reads the task after `start()` and aborts the late session itself.
- **One `maxRunMs` deadline covers start and run**: a start stuck in an MCP wait or an unanswered extension dialog has no handle yet. On the deadline the task fails with `timeout`, and a session that comes up later is aborted (`abortLateSession`). Every abort is fire-and-forget: its answer is unused, and a hung abort must not hold a slot.
- **The prompt send is not awaited** (`watchPromptRun`). `session.send({ type: "prompt" })` lasts through the MCP wait and the extension preflight (`lib/rpc-manager.ts`), so awaiting it made a hung preflight unabortable (no handle, no `sessionId`, wrapper alive forever). `start()` now returns right after `startRpcSession`; a preflight rejection rejects `done`, and `abort()` reaches the wrapper, which withdraws the MCP wait and cancels extension UI.
- **FIFO:** the runner dequeues oldest first (`listTasks` is newest first for the UI). `kickRunner` is the only runner entry point (task route, recovery, later the webhook and scheduler). It re-kicks only after a pass that started something, since a pass that started nothing with the cap full would spin. Ceiling: a slot freed early idles until its pass ends or the next external kick.
- **`recoverInterrupted` runs once per process**, on first access of a task route (`recoverOnce`): it fails the runs a dead process left `running`.
- **`spawn.ts` calls `invalidateSessionListCache()` after `startRpcSession`**; the route's call at queue time precedes the session. The route keeps `allowFileRoot(cwd)`.
- **Trigger runs** (pinned profile hash): the pin is re-checked before anything, then `enforceTriggerTools` runs after `waitUntilReady` (extension tools bind late, and the hash cannot see installed extensions) and shuts the session down on any failure, refusal included. `trigger-store.ts` holds only the allowlist and pin helpers until Phase 4.
- **The panel loads sections independently** (`Promise.allSettled`): a failing tasks request keeps the cards and shows its error, and vice versa.
